2026-10-24 사용자 요청으로 첫 버전의 요구사항과 범위를 최종 확정했다. 이후 요구사항 변경은 이 문서와 [구현 계획](../superpowers/plans/2026-10-24-ajou-study-hub.md)에 함께 반영한다. 배포 계정·허용 이메일·자격 증명 입력은 실행 단계의 설정이며, 요구사항 미확정 항목이 아니다.

## 1. 문제 정의

26-2 학기의 복습 자료는 과목별 Git 레포 안에 HTML로 작성되어 있다. 자료는 수업 날짜 또는 실험 단위로 묶여 있지만, 모바일에서 레포의 파일을 찾아 실제 웹페이지로 열어 학습하는 과정이 번거롭다. 과목을 넘나들며 자료를 찾고, 정리노트에서 문제·해설로 이동할 수 있는 공통 진입점도 필요하다.

기존 HTML에는 수식, 그림, 문제풀이 기능과 인터랙티브 설명이 포함되어 있다. 이 자료를 다시 작성하지 않고 활용하면서, 본인만 접근할 수 있는 모바일·PC용 학습 앱을 제공한다.

## 2. 해결 방안과 목표

하나의 반응형 웹앱에서 과목, 수업·실험, 자료를 순서대로 선택하고 기존 HTML을 읽는다. 과목별 레포는 자료의 원본으로 유지하고, 별도 비공개 앱 레포에서 목록과 배포용 자료를 구성한다.

배포 구성은 GitHub 비공개 레포, Cloudflare Workers Static Assets, Cloudflare Access를 사용한다. 앱과 연결 자료 전체에 본인 인증을 적용한다. 사용자가 별도의 서버를 관리하거나 PC를 계속 켜둘 필요가 없어야 한다.

첫 버전의 목표는 다음과 같다.

- 기존 5개 과목의 복습 자료를 과목·학습 묶음별로 탐색한다.
- 모바일과 PC에서 기존 HTML의 내용과 상호작용을 유지한다.
- 기존 문서 간 링크와 연결 파일을 보존한다.
- 앱과 자료를 본인만 열 수 있도록 비공개 배포를 준비한다.
- 과목 원본 파일을 수정하지 않고 자료를 갱신·배포한다.

## 3. 현재 자료와 용어

2026-10-24 로컬 조사 기준이다. 5개 원본 GitHub 레포는 모두 비공개이고 기본 브랜치는 main이다. 아래 수치는 백업·임시 폴더와 내부 제작용 HTML을 제외하고, 각 학습 묶음 폴더 바로 아래에 있는 HTML을 센 값이다. 연결 이미지·폰트·PDF 등은 포함하지 않는다.

- 과목: 기존 과목 레포에 대응하는 최상위 탐색 단위.
- 학습 묶음: 날짜, 날짜 범위, 실험 번호 또는 보충 주제로 묶인 자료 집합.
- 자료: 사용자가 열어 학습하는 개별 HTML 문서.
- 연결 자료: HTML의 정상 표시나 문서 이동에 필요한 이미지, CSS, JavaScript, 폰트, PDF, 추가 HTML 등.
- 원본: 기존 과목 레포의 파일. 앱의 수집·변환 과정은 원본을 수정하지 않는다.

논리회로실험은 실험01부터 실험06, 칩 정리로 구성된다. 실제 날짜가 없는 묶음에 임의의 수업일을 부여하지 않는다.

## 4. 사용자 스토리

1. 학습자로서 첫 화면에서 모든 과목을 보고 원하는 과목을 선택하고 싶다.
2. 학습자로서 과목별 자료 수를 보고 자료가 얼마나 준비되어 있는지 알고 싶다.
3. 학습자로서 수업 날짜와 주제로 원하는 학습 묶음을 찾고 싶다.
4. 학습자로서 최근 수업부터 확인하고 필요하면 오래된 수업으로 이동하고 싶다.
5. 학습자로서 날짜가 없는 실험·보충 자료도 자연스러운 순서로 찾고 싶다.
6. 학습자로서 각 수업에 실제로 준비된 자료 종류를 구분해서 보고 싶다.
7. 학습자로서 정리노트, 복습문제, 문제설명, 인터랙티브 자료를 앱 안에서 열고 싶다.
8. 학습자로서 기존 문제풀이 버튼, 해설 표시, 시뮬레이션과 수식이 계속 작동하기를 원한다.
9. 학습자로서 문서의 목차와 이전·다음 수업 링크를 따라 이동하고 싶다.
10. 학습자로서 연결된 강의록 PDF와 추가 설명 자료를 열고 싶다.
11. 학습자로서 모바일에서는 목록을 접고 읽기에 집중하고 싶다.
12. 학습자로서 PC에서는 목록과 본문을 함께 보며 빠르게 자료를 바꾸고 싶다.
13. 학습자로서 브라우저 뒤로가기와 새로고침 후에도 현재 과목·자료를 이해할 수 있기를 원한다.
14. 학습자로서 필요하면 HTML이나 PDF를 별도로 열고 싶다.
15. 학습자로서 서로 다른 과목의 같은 날짜 자료가 읽음·풀이 기록을 덮어쓰지 않기를 원한다.
16. 학습자로서 브라우저 저장 기능을 사용할 수 없어도 내용을 읽고 싶다.
17. 자료 소유자로서 백업·제작 파일이 학습 목록에 섞이지 않기를 원한다.
18. 자료 소유자로서 본인 인증을 거친 사용자만 앱과 개별 자료를 읽을 수 있기를 원한다.
19. 자료 소유자로서 원본 과목 레포를 바꾸지 않고 자료를 앱에 반영하고 싶다.
20. 자료 소유자로서 자료 누락이나 배포 제한 초과를 실제 업로드 전에 알고 싶다.

## 5. 기능 요구사항

### 5.1. 과목·학습 묶음 탐색

- 5개 과목을 고정된 과목 설정으로 등록한다. 폴더 전체를 무차별적으로 과목으로 간주하지 않는다.
- 과목별 학습 묶음 목록에 표시명, 날짜 또는 실험 번호, 자료 유형과 자료 수를 제공한다.
- 날짜형은 기본 최신순, 실험형은 번호순, 보충형은 별도 구분으로 표시한다.
- 날짜·묶음명·자료 제목을 대상으로 검색한다. 문서 본문 전체 검색은 제외한다.
- 검색 결과가 없을 때 검색어를 지우고 목록으로 돌아갈 수 있게 한다.
- 없는 자료 유형에는 동작하지 않는 버튼을 만들지 않는다.

### 5.2. 자료 표시와 이동

- 기존 HTML을 읽기 화면의 iframe에서 연다. 앱과 문서의 스타일·스크립트가 서로 섞이지 않게 한다.
- PC에서는 목록과 본문을 함께 표시하고, 모바일에서는 목록을 접어 본문 공간을 확보한다.
- iframe은 본인 소유의 기존 자료를 표시하는 호환 수단이다. 신뢰할 수 없는 콘텐츠를 격리하는 보안 경계로 간주하지 않는다.
- 문서의 제목, 수식, 이미지, 문제풀이와 인터랙티브 기능을 보존한다.
- 기존 링크가 다른 수집 문서로 이동하면 앱의 현재 자료 정보와 주소도 갱신한다.
- 문서 내부 앵커, 한글·공백·인코딩된 경로, 상대 경로를 처리한다.
- 외부 링크와 PDF를 별도로 열 수 있게 한다.
- 직접 주소 진입, 브라우저 뒤로가기, 새로고침으로 자료를 다시 열 수 있게 한다.
- 알 수 없는 자료 ID나 없는 경로에는 오류와 목록 복귀 수단을 제공한다.

### 5.3. 기존 HTML의 저장 기능

- 기존 문서가 사용하는 브라우저 내 읽음·풀이 저장 기능을 가능한 범위에서 유지한다.
- 과목·학습 묶음별 저장 영역을 구분해 같은 날짜의 다른 과목이 기록을 공유하지 않도록 한다.
- 예를 들어 자료구조와 기계학습의 10월 12일 정리노트에는 날짜만으로 구성된 동일한 읽음 저장 키가 존재한다. 통합 배포 시 충돌 방지가 필요하다.
- 호환 처리는 배포 사본의 문서 스크립트보다 먼저 실행한다. 기존 저장 API의 읽기·쓰기·삭제 등 실제 사용 동작을 보존한다.
- 브라우저 저장이 불가능하거나 데이터가 손상된 경우 해당 저장 상태를 기본값으로 처리하고 열람은 계속 허용한다.
- 기존 로컬 파일에서 사용하던 저장 기록의 이전과 기기 간 동기화는 포함하지 않는다.

## 6. 자료 수집·갱신 요구사항

### 6.1. 목록 생성

- 원본 복습노트의 각 학습 묶음 바로 아래에 있는 HTML을 목록 시작점으로 삼는다.
- 숨김 부속 폴더, 백업·임시·후보·제작용 폴더의 HTML은 목록 항목으로 자동 노출하지 않는다.
- 자료 유형은 과목별 파일명 규칙으로 구분하고, 알려지지 않은 유형은 기타로 표시한다.
- 문서 제목을 우선 사용하며 제목이 없으면 파일명으로 대체한다.
- 과목 ID와 정규화된 원본 상대 경로를 바탕으로 안정적인 자료 ID를 만든다. 정렬 순서나 제목 변경으로 ID가 바뀌지 않아야 한다.
- 날짜형 묶음의 연도는 학기 설정에서 가져온다. 실제 날짜가 없는 묶음은 날짜 값을 비워둔다.

### 6.2. 연결 자료 수집

- 원본의 과목·디렉터리 관계를 유지하여 상대 링크를 보존한다.
- 숨김 폴더라는 이유로 연결 이미지·CSS·스크립트·폰트를 누락하지 않는다. 현재 자료는 .pack과 .assets를 모두 사용한다.
- 복습노트 밖으로 연결되는 강의록 PDF와 추가 설명 HTML도 설정된 허용 경로 안에서 수집한다.
- HTML과 CSS 등의 정적 참조를 추적한다. 실행 중 동적으로 불러오는 파일은 명시적 추가 목록으로 보완한다.
- URL의 쿼리·앵커·인코딩을 파일 경로와 구분하고, 경로를 정규화한 뒤 원본 레포와 허용 범위 안에 있는지 검사한다. 심볼릭 링크를 통한 범위 이탈도 허용하지 않는다.
- 환경 파일, Git 메타데이터, 자격 증명, 제작 로그, 연결되지 않은 원본 전체는 배포하지 않는다.
- 원격 CDN을 사용하는 기존 자료는 첫 버전에서 유지할 수 있다. 오프라인 동작은 보장하지 않는다.

### 6.3. 갱신과 재현 가능성

- 첫 버전의 기본안은 로컬 PC에서 자료 수집·검사·배포 명령을 실행하는 수동 갱신이다.
- Git이 추적하는 로컬 파일의 현재 내용을 입력으로 사용한다. 추적되지 않은 파일은 명시적으로 추가한 경우에만 포함한다.
- 배포 보고서에 과목별 원본 커밋, 입력 파일 해시, 로컬 변경 여부, 결과물 해시와 생성 시각을 기록한다.
- 앱은 원본 변경을 자동 커밋하거나 push하지 않는다.
- 동일 입력으로 목록과 자료 구성이 같아야 한다. 생성 시각 등 메타데이터는 콘텐츠 비교에서 구분한다.
- 원본 레포의 최신 원격 main을 자동으로 가져오거나 매 push에 연동하는 기능은 후속 범위다.

| 초기 저장 | 기존 HTML의 기기 내 저장 유지, 과목별 충돌 방지 | 확정 |
| 갱신 | 초기 수동 갱신·배포 | 확정 |

자료 수집기, 목록 생성기, 읽기 화면, 저장 호환 계층, 배포 검사기를 구분한다. 목록 생성과 수집 결과는 브라우저나 클라우드 계정 없이 검증할 수 있어야 한다. 앱 실행 중에는 과목 레포에 직접 접근할 필요가 없어야 한다.

## 8. 비공개 배포와 비용

- 신규 앱 레포도 비공개로 만든다. 기존 과목 레포의 공개 범위는 변경하지 않는다.
- Cloudflare Access에서 이메일 한 주소만 허용한다. 이메일 도메인 전체나 모든 로그인 사용자를 허용하지 않는다.
- 권장 기본값은 Cloudflare 계정에 사용하는 본인 이메일이다. 실제 허용 주소는 배포 설정 시 입력하며, 비밀키와 로그인 코드는 레포에 저장하지 않는다.
- 이메일 일회용 코드 인증을 기본으로 한다.
- 앱 목록뿐 아니라 개별 HTML, 이미지, PDF, 연결 파일과 운영·미리보기 주소를 보호한다.
- 인증되지 않은 요청은 자료 본문을 반환하기 전에 차단해야 한다. 클라이언트 화면에서만 숨기는 방식은 사용하지 않는다.
- 먼저 자료가 없는 빈 앱을 배포하고 Access를 설정한 뒤, 비로그인·다른 계정의 접근 차단을 검증한다. 검증을 마친 후 실제 자료를 업로드한다.
- 정확한 허용 주소와 접근 제어 설정을 확인할 수 없는 상태에서는 실제 학습 자료 업로드를 막는다.
- 기존 자료에 대한 자동 오프라인 캐시나 서비스 워커를 첫 버전에서 추가하지 않는다.
- 무료 요금제를 사용하고 유료 플랜·추가 기능을 자동 활성화하지 않는다. 사용량 한도를 초과하면 배포를 중단하고 원인을 안내한다.
- 문서 작성 시 확인한 Workers 무료 정적 파일 한도는 20,000개, 파일 하나당 25MiB다. 구현·배포 시 최신 정책을 다시 확인하고 결과물을 검사한다.
- 진도 저장 서버, 대용량 동영상 저장과 별도 유료 도메인은 초기 구성에 포함하지 않는다.

## 9. 테스트 결정과 완료 기준

테스트는 내부 함수 구성보다 사용자 동작과 배포 결과를 검증한다. 가장 큰 검증 경계는 원본 자료 집합을 입력해 실제로 열 수 있는 배포 결과물을 얻는 전체 흐름이다. 경로·저장 충돌 같은 실패 조건은 작은 대표 자료로 재현한다.

과목 레포에는 상대 링크 검사와 자료 검증 도구가 존재한다. 그 검증 항목을 참고하되 기존 마이그레이션 스크립트를 원본에 실행하거나 앱 테스트의 필수 의존성으로 사용하지 않는다. 앱 전용 단위·브라우저·실제 자료 검사를 추가했다. 현재 결과와 남은 클라우드 검증은 [구현 상태](../operations/implementation-status.md)에 기록한다.

| ID | 검증 내용 | 통과 기준 |
| --- | --- | --- |
| AC-01 | 기준 자료 수집 | 조사 당시 입력에서 5과목·53묶음·217개 HTML이 목록에 포함되고 백업·제작 HTML은 제외됨 |
| AC-02 | 자료 증가·감소 | 원본 자료가 바뀌면 목록이 갱신됨. 기준 수치를 영구 고정값으로 사용하지 않음 |
| AC-03 | 연결 파일 | 수집한 문서의 정적 로컬 참조에 설명되지 않은 누락이 없고, 한글·공백·인코딩·앵커 링크가 동작함 |
| AC-04 | HTML 로딩 | 모든 목록 HTML을 브라우저로 열 때 누락 리소스와 실행 오류를 검사함 |
| AC-05 | 기존 기능 | 과목별 대표 문서의 수식·이미지·문제풀이·인터랙티브 기능이 실제로 작동함 |
| AC-06 | 모바일·PC | 390px 모바일과 1440px PC 화면에서 과목 선택·목록 접기·본문 열람이 가능하고 앱 UI가 잘리지 않음 |
| AC-07 | 탐색 | 내부 링크 이동, 별도 열기, 뒤로가기, 새로고침, 직접 주소 진입이 동작함 |
| AC-08 | 저장 충돌 | 같은 날짜의 다른 과목에서 읽음·풀이 기록이 서로 바뀌지 않음 |
| AC-09 | 저장 불가 | 브라우저 저장을 막아도 자료 열람이 가능함 |
| AC-10 | 원본 보존 | 수집·변환 전후 원본 파일이 변경되지 않음 |
| AC-11 | 배포 범위 | 금지 파일·허용 범위 이탈·파일 수·파일 크기 제한 위반이 업로드 전에 차단됨 |
| AC-12 | 비공개 접근 | 비로그인과 허용되지 않은 계정으로 목록·개별 HTML·이미지·PDF·미리보기 주소의 자료 본문을 받을 수 없음 |
| AC-13 | 본인 접근 | 허용 계정이 모바일·PC에서 인증 후 자료를 열 수 있음 |

비공개 접근 검증은 실제 클라우드 설정에서 수행한다. 로컬 테스트나 설정 파일만으로 배포 보안 검증을 완료했다고 간주하지 않는다.

원본의 기존 깨진 링크, 외부 CDN 장애와 앱의 수집 오류를 구분해 보고한다. 설명되지 않은 누락은 배포 실패로 처리한다. 의도적 예외가 필요하면 항목과 이유를 명시하고, 조용히 제외하지 않는다.

## 10. 범위 밖

- 여러 사용자, 공유·초대 기능과 사용자별 권한 관리.
- PC·모바일 사이의 진도·오답·북마크 동기화와 기존 기록 이전.
- 별도 북마크·최근 학습 기능. 최초 아이디어에는 있었지만 이번 첫 버전의 필수 범위로 확정하지 않았다.
- 앱 안에서 복습노트를 작성·수정하거나 파일을 업로드하는 기능.
- 모든 강의노트·교과서·과제·영상의 자동 공개 목록화.
- HTML을 새 콘텐츠 형식으로 변환하거나 기존 학습 UI를 전면 재작성하는 작업.
- 전체 본문 검색, 추천 복습·간격 반복·성적 분석 기능.
- 오프라인 다운로드, 자동 캐시와 설치형 PWA 전용 기능.
- 앱스토어 배포와 네이티브 모바일·데스크톱 앱.
- 매 과목 push에 연동되는 자동배포와 원격 레포 자동 동기화.
- 대용량 동영상 호스팅, 별도 도메인 구매와 유료 서비스 활성화.

## 11. 진행 단계와 남은 설정

1. 완료: 앱 레포에 PRD를 저장하고 첫 버전 요구사항을 최종 확정한다.
2. 완료: [구현 계획](../superpowers/plans/2026-10-24-ajou-study-hub.md)을 작성한다. 구현 착수 전 계획을 검토하고 실행 방식을 선택한다.
3. 완료: 자료 수집과 목록 생성, 모바일·PC 탐색과 읽기 화면을 구현했다.
4. 완료: 원본 호환성과 자료 누락·로컬 배포 범위를 검증했다.
5. 미실행: Cloudflare 계정, 실제 허용 이메일과 배포 자격 증명을 설정한다.
6. 미실행: 빈 앱으로 접근 제어를 검증한 후 실제 자료를 비공개 배포한다.

요구사항 확정, 구현 계획, 로컬 앱과 실제 자료 검증을 완료했다. 실제 입력에서 5과목·53묶음·목록 HTML 217개와 연결 HTML 3개를 확인했고, 대표 42조합을 검증했다. Cloudflare 리소스 생성, 자격 증명 등록과 실제 학습 자료 업로드는 실행하지 않았다. 배포 도구의 로컬 구현·검토 결과와 실행 조건은 [구현 상태](../operations/implementation-status.md)에서 구분한다.

실제 로그인 허용 이메일은 아직 제공되지 않았다. 갱신 방식은 수동 배포를 기본으로 두며, 자동배포로 변경하는 경우 레포 간 권한과 갱신 흐름을 추가 설계한다.
