# 최소 자동 갱신 설계 — 2026-10-27 범위 조정

사용자 우려: 개인 학습 사이트 자동 갱신에 비해 초기 완료 조건이 과도하게 커졌다. 기존 계정·접근 보호·비밀키·원본 자료를 유지하며 실제 사용 흐름부터 완성한다. 이전 2026-10-26 설계의 운영 장치 확장은 이번 최소 범위의 선행 조건으로 쓰지 않는다. 기존 코드와 리소스를 삭제하거나 설정을 해제하지 않는다.

## 먼저 완성할 동작

과목 5개 main push 또는 앱 main push → 앱 main의 고정 GitHub Actions workflow → 다섯 main SHA 고정·선별 체크아웃 → 빌드·필수 검증 → 검증한 동일 결과물의 기존 Cloudflare Worker 배포 → 보호 상태 확인. concurrency는 기존 study-hub-production, cancel-in-progress:false를 유지한다. 실패 결과와 실행 링크는 Actions에서 확인한다.

## 유지할 필수 보호

- 기존 ajou-study-hub와 workers.dev 주소, johnshin617@gmail.com 한 명 허용, 이메일 OTP, Cloudflare Access 정책, preview 비활성, Free 운영을 유지한다.
- 과목 원본을 수정·커밋·덮어쓰지 않는다. 원격 최신 main 사용이라는 기존 선택을 유지한다. 과목에 추가할 파일은 알림 workflow 하나씩이다.
- 기존 Reader/Dispatcher App 설치·권한 분리는 재사용한다. 토큰은 필요한 단계에만 전달하고 Reader는 자료 실행 전 폐기한다. 배포키는 GitHub Secrets에 보관하며 로그·자료 브라우저 단계에 노출하지 않는다.
- build와 verify는 같은 SHA·체크아웃·소스 설정을 사용한다. 검증 후 바뀐 결과물이나 소스는 배포하지 않는다. 기존 봉인 사본과 고정 Wrangler 대상 설정을 재사용한다.
- 배포 전후 현재 Access 의미를 승인한 baseline과 대조하고 비로그인 자료 요청이 인증으로 차단되는지 확인한다. 배포키에는 Access 정책 쓰기 권한을 주지 않는다.
- 수동 배포의 기존 24시간 검증 규칙은 유지한다. 자동 경로는 승인한 초기 baseline과 현재 보호 상태를 사용하며 OTP 쿠키를 CI에 넣지 않는다.
- 자료 dist/HTML/PDF는 로그나 Actions artifact로 올리지 않는다. 동일 job에서 검증하고 배포한다. 자체 관리 main과 잠근 도구를 신뢰하는 일반 CI 운영 모델이다.
- 업로드 결과가 불명확하면 성공으로 기록하거나 자동 재시도하지 않는다. 실패·현재 배포 버전·정지 방법을 운영 문서에 남긴다.

## 이번 완료 조건에서 제외

전용 배포 ledger 저장소 및 Ledger App 연결, 원격 CAS/충돌 실증, 회수·복원 실증, 별도 컨테이너·방화벽 격리, 장기 유휴 최적화, 변경 없는 입력의 업로드 생략. 이미 만든 상태 저장소·App·키·테스트 Worker·기록은 보존하고 일반 배포 흐름에서 사용하지 않는다. 자동 회수나 전역 pending 상태 차단을 이번 버전의 보장으로 주장하지 않는다.
