# Android WebView 앱 설계

## 목적과 범위

기존 아주 학습 허브를 Android에 설치해 전체 화면으로 사용한다. 사용자가 선택한 방식은 Kotlin 네이티브 앱의 WebView이며, 자동 갱신되는 기존 비공개 사이트를 인터넷으로 불러온다. 웹앱과 학습 자료를 APK에 포함하거나 별도의 동기화 시스템을 만들지 않는다. 기존 사이트와 자동 게시·Access 정책은 그대로 사용한다.

## 검토한 방식

- Kotlin 네이티브 WebView: 작은 앱에서 Android 탐색과 웹 표시를 직접 처리한다. 사용자가 선택했다.
- Capacitor: 웹과 네이티브 확장에 유용하지만 현재의 웹 표시 목적에는 추가 도구와 설정이 필요하다.

## 동작

- 앱을 열면 기존 운영 HTTPS 주소를 WebView로 연다. 사이트의 JavaScript, DOM 저장소, 쿠키 및 iframe이 정상 작동하도록 설정한다. 자료와 인증 정보를 앱에 하드코딩하지 않는다. 운영 주소는 기존 로컬 배포 설정에서 확인하고 빌드 설정으로 주입한다.
- 화면은 웹 콘텐츠에 집중하는 전체 화면으로 구성한다. 시스템 상태·내비게이션 영역을 숨기되 일시적으로 제스처로 다시 표시할 수 있게 한다. 화면 잘림, 키보드 및 제스처 탐색을 확인한다.
- Cloudflare Access 이메일 OTP 인증을 WebView에서 거쳐 세션을 유지한다. 인증 리다이렉트가 작동하도록 필요한 호스트를 확인한다. 인증 우회나 Access 정책 변경은 하지 않는다.
- Android 뒤로 가기는 웹 탐색 기록이 있으면 그 기록을 따라가고, 없으면 앱의 기본 종료 동작을 따른다. 웹앱의 문서·앵커 이동도 대표 사례로 확인한다.
- 운영 사이트와 인증에 필요한 탐색은 앱 안에서 처리한다. 외부 링크, 새 창과 PDF/다운로드는 사용자에게 접근 가능한 Android 앱으로 열거나 처리하며, 인증이 필요한 자료가 실제로 열리는지 검증한다. 안전한 HTTPS 및 필요한 시스템 링크만 취급하고 인증 쿠키를 임의의 외부 호스트에 전달하지 않는다.
- 연결 실패 시 사용자가 재시도할 수 있는 오류 화면을 보여준다. 오프라인 열람은 보장하지 않는다.
- 웹 저장소와 로그인 세션은 Android 앱의 WebView에 보관한다. 기존 브라우저의 저장 기록·세션과 자동으로 합쳐지지 않는다. 앱 삭제나 데이터 삭제 시 소실될 수 있다.

## 구현 및 검증 경계

- Android 프로젝트는 저장소 내 독립 디렉터리에 둔다. 패키지명, 최소 Android 버전, 빌드 도구, 아이콘과 세부 오류 UI는 기존 환경과 호환성을 확인해 구현자가 정한다.
- 설치 가능한 디버그 APK를 빌드하고, 가능한 Android 에뮬레이터 또는 실제 기기에서 최초 OTP 로그인, 목록, 대표 HTML의 상호작용과 이미지, 문서 이동·뒤로 가기, 세션/저장 유지, 외부 링크·PDF, 연결 실패와 재시도를 검증한다. 기기나 로그인 등 환경이 없으면 자동 검사와 미검증 항목을 구분해 보고한다.
- Play 스토어 게시, 릴리스 서명, 푸시 알림, 오프라인 자료 다운로드, 브라우저 기록 가져오기는 범위 밖이다.
